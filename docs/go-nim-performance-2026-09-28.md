# Go 与 Nim 性能改动记录

本机 Go 默认 L0 Core 在 Linux 6.12.107 x86_64、2 个逻辑 CPU 上经真实 broker/agent/client 部署运行 iperf3。每项单流 TCP 测量 3 秒，数据经过 Shadow6；回环直连夹具基线不计入下表。原始报告的机器环境字段相同，`commit` 为空（本机工作树测量）。

| Go 版本 | 正向接收 Mbit/s | 反向接收 Mbit/s |
|---|---:|---:|
| 修改前，1 轮 | 3.49 | 6.63 |
| 修改后，第 1 轮 | 289.50 | 321.86 |
| 修改后，第 2 轮 | 303.54 | 296.35 |
| 修改后，第 3 轮 | 315.72 | 332.12 |
| 修改后，中位数 | 303.54 | 321.86 |

Go 将 KCP 拥塞控制应用到桌面及 BSD 预算，同时保留已有窗口和 socket 缓冲上限。原配置请求 32 MiB UDP socket buffer，但本机内核 `rmem_max` / `wmem_max` 均为 212,992 字节；单独查询 socket 时，实际授予的接收/发送缓冲均为 425,984 字节。此前关闭拥塞控制会让大窗口在如此有限的缓冲下突发发送。启用拥塞控制后，本机实测比改动前高约两个数量级。空数据 flush 初始化 KCP 窗口，保持既有小回复立即关闭行为。线格式、认证和数据帧保持不变。

这只是单台双核机器上的短测，3 轮间仍有波动；三轮都未达到 1 Gbit/s，不能据此宣称 WAN、其他平台或高并发场景达到目标。两次测量含转发夹具的连接重置诊断，但 iperf 接收报告有效、测试结果为 `ok`；可在 CI 稳定性数据中继续观察。

Nim 的有界 RTC 回调队列现在用条件变量唤醒消费者，消息空闲时最多等待 1 ms，避免每次轮询固定睡眠；队列容量、消息顺序和满队列背压不变。Nim Core 的实际 iperf 吞吐尚未重测；本次只做了 `nim check` 和 C 队列测试，没有编译 Nim Core。

验证：Go 默认 L0 构建和 `go test ./...` 通过；针对 KCP 双栈、小 UDP 缓冲、大流量双向半关闭及 AEAD 的 Go race 测试通过。Nim `nim check`、C 队列 1000 条有序消息测试，以及 AddressSanitizer/UndefinedBehaviorSanitizer 下的同一队列测试通过。没有执行全仓构建/审计，也没有本地编译 Idris、Pony 或 Nim Core。
