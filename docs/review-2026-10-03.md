CLI/control/install paths, source syntax and offline deployment checks. This is

## Preserved goals and remaining work

- Native ready-event/endpoint discovery and protocol-level readiness across all
  Core families. Current Named Service readiness is explicitly `process-alive`;
  `connect NAME` returns metadata, while Public6 invitation connect keeps its
  original provisioning behavior.
- Portable process supervision beyond Linux pidfd, and real native twelve-Core
  deployment E2E with current rebuilt artifacts. No cross-family wire
  compatibility is implied.
- Encrypted outer transport, numeric IPv6/Unix/inherited-descriptor endpoints,
  and native WebRTC/SCTP envelope adapters. Current EPE authenticates admission
  and UDP records; it does not encrypt stream payloads or replace native security.
- Replay state is bounded and process-local; restart-spanning protection needs
  key rotation or persistent replay state. Clock synchronization is required for
  the UDP timestamp window. Native listeners outside the configured loopback
  endpoint require separate deployment inspection.
- Native runtime output is discarded by the service supervisor. Foreground native
  validation remains the diagnostic path for configuration/startup failures.
- Registry files produced by the old simulated lifecycle must be backed up and
  recreated explicitly; they are not automatically trusted as process records.

These are specific limits and follow-up requirements, not removed product goals
and not a claim of vulnerability-free software.
